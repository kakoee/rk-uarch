# Concrete transition, publication and recovery sequence

This is executable planning for a later separately authorized transition. None of the
installation, freeze, staging, generation or adoption steps below ran in this checkpoint.
Javid is the human policy/artifact decision-maker; no generation operator or human L1
assignee is invented. Existing source/adopted inputs remain the only current pair.

1. **Reconcile exact inputs, A+B/coordinator.** Pin final M patch and any actual loader,
   registry/profile/spec/data reads; rerun B's closure and guards. The currently audited
   M is an early schema-only patch, not future importer/exporter code. Attach its exact
   patch hash and repair hash to the installation request. Resolve M approval/signing
   trust and fixture joins. Tool/licence acceptance releases K1 separately; it does not
   authorize this migration. No new vote on already accepted D2 is needed.
2. **Human installation release.** Javid authorizes exact protected M installation plus
   unchanged repair and prospective enforcement transition at a named source revision.
   Coordinate a bounded publication window with A so reached inputs cannot change while
   generation is in progress. No server allocation or artefact operation is implied by
   ordinary proposal approval. If repair remains unready, obtain the explicit retained-
   enforcement/budget decision before M install; do not silently waive currentness.
3. **Local source commit S on normal main; hold push.** In the authorized integration
   checkout install only reviewed M/repair/runtime files, run applicable scratch/source
   checks with no source-mutating tests, and commit using normal human/owned hooks. Do
   not push S as a coherent current main tip: the old artifact is expected to refuse it.
   Do not rewrite history, bypass hooks, set a human flag as an agent, or relax checks.
4. **Freeze S and complete inputs, human lifecycle.** Human stages the exact full nominal
   input set using reviewed tooling, new support-policy/support-files records and the
   actual computed closure; retain1,008 nominal records/four real refusals, PARAMS,
   precision/execution/model/source identities and sidecars. Bind full generator SHA,
   unchanged oracle-program SHA, lock/environment, upstream pin and actual input digest.
   This step is not performed by B; a proposal JSON is not frozen input provenance.
5. **Human two-process generation.** On clean committed S and pristine pinned upstream,
   in the verified external locked environment, the authorized human runs the ordinary
   guarded generator twice from identical inputs. Capture actual created then verified-
   identical outcomes. No agent-generated replacement, hand-edited output, copied
   environment identity, favorable rerun or output-equality currentness waiver.
6. **Complete candidate audit before adoption.** Check strict new-policy support, all
   manifest/outer-copy/pin/environment/attribution joins; compare old/new semantic query
   identities over every count/duration/null/refusal, not samples. Expected numerical
   delta is zero; any difference is a finding requiring explicit disposition. Metadata
   necessarily changes (policy/inventory/input and vendor hashes, outer manifest). Test
   unknown/stripped policy, retained drift, shadows, relevant/unrelated changes and actual
   positive currentness. Human generation is indispensable to the real positive test.
7. **Separate human adoption commit C.** After reviewing exact candidate identity and
   semantic/provenance delta, Javid approves complete artifact/protected binding adoption.
   Preserve prior pair in Git; update all required adoption bindings coherently, never
   just support-files.json. Use normal hooks and record S, input hash, candidate manifest,
   approval and C. Verify strict vendor/contracts, both mypy commands, Ruff/imports,
   old/new schema freshness, applicable legacy/rotary/replay/comparison regressions and
   one integrated suite. Guarded consumption must prohibit producers.
8. **Publish coherent tip only.** Fetch before push. If peer changes any bound source,
   initializer, scripts, lock or reached data, stop publication, re-audit and restart the
   freeze/candidate as required; no rebase relabels stale generated inputs current.
   Pure proposal changes can integrate normally after affected checks. Push S+C together
   only when final tip has a complete compatible pair. Main must never be updated to S
   alone. Verify remote ancestry. Report asynchronous CI as pending with run link; do
   not poll or call a local pass hosted acceptance. Hosted/fresh-clone sprint closure is
   a separate later task, not supplied by this transition proposal.

## Exact refusal/recovery expectations

| Condition | Expected refusal / response |
| --- | --- |
| Current adopted artifact + repaired source | `vendor-rk: input support inventory changed` (observed); do not use --historical for acceptance |
| Rehashed synthetic bound derive.py drift or substituted hash | `input support bytes changed: src/rkuarch/hw/derive.py`; restore exact reviewed source or begin new freeze |
| Missing inventory entry/new reached import/new script/data-family file | `input support inventory changed`; audit inclusion and refreeze, never omit the dependency |
| Unknown/extra/stripped/substituted policy | `unrecognized input support policy` for unknown policy; stripped policy routes strict legacy enumeration and refuses mismatched inventory |
| New importable __future__ shadow | `unreviewed import name: scripts/__future__...`, marker absent before refusal; remove unreviewed shadow/review source |
| Unsupported bootstrap | `unsupported import-guard bootstrap`; use approved CPython/frozen-os environment, no exemption |
| Legacy intact artifact against changed full generator | `GENERATOR current incompatibility: generator script fingerprint differs`; integrity is not currentness |
| Source writes from policy tests | `test attempted write to real source root`, before mutation; retain throwaway roots/origin checks |
| New-policy human positive absent | Explicit skip; blocks migration completion, never replace with synthetic adoption |
| Different candidate bytes on second generation | Ordinary occupied-destination refusal; preserve difference, investigate and restart candidate if inputs drifted |
| Failed comparison/currentness after C but before push | Hold publication; preserve evidence and return to exact source/input/candidate audit |

Before any publication, abandonment restores the entire compatible local source/artifact
pair via reviewed normal commits; do not discard peer/user work. After publication,
rollback is a new normal human-approved complete-pair adoption/revert, with strict tests,
not source-only revert, metadata editing or force push. A prior source commit paired with
a later artifact is not automatically compatible. Upstream pin alone is not identity.

Known limits remain those already accepted: static import analysis is conservative,
non-import reads need explicit registration, normal trusted startup/external environment
and no concurrent source race are premises. Source-write audit hooks are defence in depth,
not an OS sandbox. The narrower policy still binds every reached file wholesale and all
scripts Python; an uncalled function, TYPE_CHECKING import or initializer cannot be ignored.
