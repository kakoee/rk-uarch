### J1 — raw clock primitive versus zero-cycle owned job

Independently derived: at 1.2 GHz, rounded edges are 0, 834, 1667, 2500 ps.
The first edge at or after 835 ps is 1667 ps. Therefore raw
`next_edge(1200000000,835,0)` must return 1667 ps.

The installed K1 `Delay::Cycles` branch deliberately returns the actual owner-grant
timestamp when cycles are zero. A job granted at 835 ps therefore ends at 835 ps.
This is consistent with U0011's owned zero-duration rule. The 832 ps difference is
between operations, not floating-point error or a failure in the non-executing loader.
B's K06-02 currently projects the primitive answer into that job's result; that projection
cannot stand as an accepted public expectation under the existing zero-job law.

Recommendation: preserve the original bytes and record a prospective split into raw-edge
and owned-job obligations, each with its own discriminator. Do not change the clock
primitive, overwrite B's frozen answer, erase the row or alter reviewed K1 semantics to
make them agree. The exact public/private mapping and any necessary carrier clarification
must be reconciled before accepting the revised corpus. No new interface is approved here.
