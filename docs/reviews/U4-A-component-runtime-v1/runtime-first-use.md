This is a new component identity path. The installed model is native-intervals/2,
observations/3 and profile/2. K2 source, identities, receipts and sealed roots are not
component authority. No real selector, HostRecord, placement or public successful job

## Implemented ordinary boundary

`component_records.py` defines separate component construction/payload/receipt/selector
shapes. BuildInputs/2 intentionally differs from historical component BuildInputs/1;
old record formats are not coerced. Construction trust/2 has private-only purpose and
is refused by the ordinary native executable. The fixed-delay reader remains separate.

`component_host.py` admits the full selected profile/case inventory and every closure
point, including explicit checkpoint-B transport fixtures. It binds exact policy,
registry, profile2, engine, sources, generated output, both executable receipts,
consumer closure, actual import origins and Python dependency bytes. Immutable setup
is prepared once per bounded ComponentSession; each call/replay rechecks current bytes,
imports, capability and budget. Open executable descriptors are rehashed and require
read-only executable mode. Fixed root-owned selector discovery is not caller selectable.
Shape-valid private payloads do not authorize either public entry point.

`component_runner.py` routes model2→observations3→check_v3 before consuming observations.
The prepared path additionally invokes B's exact consume_case wrapper and separately
bound consumer pins/selection/literals. Saved replay reads exact raw jobs, needs no
producer preparation and retains both consumers. Existing bounded descriptor exchange
and refusal framing are reused; it does not relax limits or grant raw negative bypass.

The Rust protocol selects installed /3 for model2/profile2. The ordinary construction
binary rejects private component trust before dispatch. K2 compiled trust is restricted
to fixed-delay/1, preventing component use of old compiled K2 profiles. Positive native
controls use explicit cfg(test) synthetic anchors; this is not public process success.
A test-only runtime-entry counter witnesses refusal before Runtime::run, with a literal
positive control of one entry; it is neither a production observation nor a timing law.

## D3 remains unapplied

`proposals/D3-unapplied.patch` adds a separate refusal-only module. A distinct fixed
negative selector, exact negative decision/review and immutable inventory are required;
positive authority alone is insufficient. The only caller argument is a finite case ID.
Raw bytes, profiles, expected code/pointer and executable come from the independently
bound records. Each actual refusal must match canonical status/streams/code/pointer;
success, malformed output, wrong refusal, stale bytes or exceeded budgets fail. There
is no caller raw/profile/digest override or bypass flag. The envelope does not claim
zero dispatch; separate native runtime-entry evidence supplies that limited fact.
The future D3 compiled profile set must be explicitly reviewed/rebuilt if it differs
from the positive construction profile set. No proposed negative selector was created.
