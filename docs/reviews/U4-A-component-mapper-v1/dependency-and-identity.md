`dependency-audit.json` records actual clone/module origins, SHA256 source inventories,
observed local opens and conservative AST closure including function-local imports and
package initializers. No external package was added; no initializer was changed. Current
static closures contain26 mapper files,27 assembly files and26 replay-loader files. Counts

Actual production paths:

- Mapper takes caller-supplied PreparedOp and HardwareSpec objects. It imports installed
  prepared/mapped/hash/hardware definitions; validate_prepared_op retains its function-local
  comparison import. It reads no file, registry, profile, model, coefficient or environment.
- Assembly imports the replay validator and installed carriers, not the mapper. Its inputs
  are explicit point, assumptions, producer, rank/admission and future engine/trust objects.
  It neither discovers source IDs nor fills profile/registry entries. Source provenance is
  caller-supplied; it is not authenticated human authority.
- Replay imports installed carriers/hash and pathlib only. `_load` reads the one named file;
  `_loads` reads supplied bytes. JSON parsing and installed admission/hash verification are
  validation, not mapping/coefficient production. Canonical exclusive export validates before
  opening the destination and never repairs hashes. There is no native subprocess, executable
  discovery, host selector, installed root or ambient profile read.
- Tests/audit read explicitly named installed mapped fixtures. New fixture authoring reads
  the audit's source-hash closure plus component/resident-profile/registry fixtures and writes
  only review-package inputs. Synthetic author profile/registry hashes are test anchors;
  none claims a human approval or accepted runtime deployment. Tests run three isolated
  relocated imports with mapping, assembly, workload/coefficient producers, engines and
  subprocess imports blocked; exact local module origin and canonical input bytes are checked.
