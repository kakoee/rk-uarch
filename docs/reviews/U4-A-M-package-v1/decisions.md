# Exact M encoding decisions and installation boundary

Accepted U0011 laws are unchanged. This package makes the following remaining encoding
choices concrete for Javid's protected acceptance; none is an implicit runtime default.

1. Add `mapped.py` and its dedicated generator only. Direct submodule imports; no changes
   to old roots, root re-exports, hash dispatch, old generators, hardware derive/export or
   analytic execution. Twelve generated roots include the explicit `MappedAssumptions`.
   The full patch path list and SHA are in package.json.
2. `MappedAssumptions` gives fixed semantic law identifiers and a hashed limitation list.
   Bundle and job embed the same full object; hash-only missing assumptions are refused.
   Model source uses a strict original-format union containing the **entire original
   bundle**, its identity and original AssumptionSet. Original point/intent/hardware and
   coefficient identities/joins are checked before B's UnsupportedWorkloadScope. Original
   analytic assumptions are never rewritten into mapped assumptions. Prepared-model
   execution and complete model mapping remain unadmitted; native model support needs R/T.
3. Hardware resolution is a complete, deterministic JSON-pointer scalar projection, bound
   to full HardwareSpec. Each numeric float is represented by its exact decimal rational
   numerator/denominator, with bounded 128-bit intermediates. Integers stay strict integers;
   structural strings/bools/null and provenance leaf paths stay explicit. Empty structures
   remain bound by the full spec identity. No lossy clock periods or analytic peak fallback.
   Schema/profile clocks are positive integer Hz; service-time ratios use reduced 128-bit
   pairs, while wire timestamps and completed counters are u64. This pointer encoding,
   rather than hundreds of duplicated hardware carrier fields, is the exact choice to review.
4. Buffers additionally carry explicit nullable `slot_index` (0/1), routes have their own
   sorted IDs, and coverage rows bind compute job/group/repeat/origin/extents. The prototype
   checks DAG closure, complete row partition, observed buffer readers/final-consumer joins,
   capacity/banks, live alias dependencies, double-buffer reservation, fragmentation and
   XY routes. It never retile/reassigns work. The fixed-delay union carries only duration,
   ID and owner; cycle setup is exclusively inside MappedEngineJob.
5. Profile entries bind **clock_setup_hash** in addition to graph/point/hardware/clock/
   seed/case selection. This hashes the ordered job-only ClockSetup array and avoids a
   profile↔job cycle. Changing domain/start/cycles requires a new reviewed entry. A profile
   has finite named outcomes, no wildcard/range. Kernel graph/point can be identical across
   independently approved clock cases; their profile/job identities differ.
6. `admit` requires host-selected **trusted_registry_hash** and **trusted_profile_hash**;
   `validate_job` additionally requires the expected engine identity. Parsing the embedded
   job/profile objects checks consistency only, never confers launch authority. Recommendation
   for the remaining signer choice: use Javid's exact published Git acceptance record to
   freeze these hashes in the reviewed loader's authority inputs. Do not add a new crypto
   dependency or treat caller-supplied JSON as approval. Coordinator/Javid must accept this
   mechanism and B's actual corpus/profile/registry hashes before public qualifying tests.
   Neither a path nor a CLI flag creates that trust. Changing the authority inputs binds
   loader identity and requires B's actual read/dependency audit.
7. Count channels reuse Counts/ExtCounts keys and number serialization, with native-boundary
   rejection of bool/string coercion. Useful matrix=2×completed MAC, vector=arithmetic+casts,
   HBM counts=payload; transaction bytes are separate. Per-op/results use strict typed
   observations. Component `u_c0_duration_ps` is null; no analytic production code computes
   or repairs a native duration. Missing/incomplete output cannot parse as a complete result.
8. Result parser prototypes check job/engine/admission/owners, complete job/request inventories,
   observed work/count sums, interval-union busy time and critical-path partition. These
   checks have **no completed native positive fixture yet**. Event causality, exact service
   observations, all deterministic ordering, full hardware unrepresented ledger, per-op
   observation joins and fault discrimination must be tested against actual K2/B output.
   Schema/prototype acceptance is not qualification of those runtime mechanisms.
